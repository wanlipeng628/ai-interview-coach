# 出题质量控制

> 这一层防的是「面试官问得不专业」的三类硬伤：**重复出题**、**一次问两个问题**、**问到一半被截断**。
> 它们在用户侧都是当场能察觉的体验瑕疵，但在自动化指标里经常显示为 0——所以本文的重点不只是规则，
> 还有「怎么验证规则真的生效」。

## 1. 三类违规

| 类型 | 现象 | 用户感受 |
|---|---|---|
| 重复题 | 同一事实点换个说法再问一遍 | 「刚才不是问过了吗」 |
| 一次问两问 | 一句话里串两个疑问，句末只有一个问号 | 不知道该答哪个 |
| 截断丢内容 | 题面被切掉半句，只剩问候语或残句 | 这题没问完 |

第二类最容易被自动化指标漏掉：模型用**一个问号**串两个疑问，按问号切分和按连接词匹配都抓不到。
2026-11-14 的盲评里，96 道追问有 13 道是这种形态（13.5%），而当时的检测计数全部显示 0。

## 2. 四层防线

```
预防 ── prompt 硬约束（SYSTEM_PROMPT 提问规则 1~11 条）
  ↓
检测 ── detect_multi_question()  一次问两问
        _is_repeated_question()  重复题
  ↓
修复 ── 重生成一次（InterviewService._repair_question，同步/流式共用）
  ↓
兜底 ── 重复题落到静态题库；多问修不好就保留原题 + warning，不阻塞用户
```

三条设计原则：

1. **只识别不擅自改写**。把「，以及……如何？」截掉会留下没有疑问词的残句，比两问更糟。
2. **重生成最多一次**，不循环。失败保留原题，宁可问得不好也不要卡住用户。
3. **检测跑在截断之前**。模型原始输出算出的 `multi_question_detected` 要传给服务层，
   否则「Q1？Q2？」被截成「Q1？」后，服务层再检测就永远是 False（这个 bug 真实发生过）。

## 3. 重复题的判据

两件事配合：**让模型看得见**，和**兜底拦得住**。

### 3.1 全量已问清单进 prompt

出题时 `history` 只喂最近 12 条消息（约 6 轮）做对话上下文，另带一份
「已问过的问题（全部，不得重复）」清单。28 轮会话里第 24 轮出题时，
模型能看见第 3/10/17 轮问过什么；只靠 6 轮上下文时它看不见，必然回锅。

`asked_questions` 参数不传时自动从 history 抽取，老调用方行为不丢。

### 3.2 字面判重阈值 `QUESTION_DUPLICATE_THRESHOLD`

相邻两字 Jaccard 相似度，默认 **0.35**（原为 0.72）。

依据是 15 场真实会话（71 道题）的回归：

```
合理递进追问   0.025 ~ 0.143     （同一项目往更深的层次走）
真重复         0.198 ~ 0.642     （同一事实点换措辞）
```

**两段是重叠的，不存在一个阈值能既抓全又不误杀。** 0.35 只负责拦下最明显的 4 对，
其余靠 prompt 那条清单在生成阶段预防。想调低要先用历史会话量误杀。

## 4. 一次问两问的检测规则

`detect_multi_question()` 命中任意一条即判定：

1. 两个及以上问号。
2. 分句以「以及 / 同时 / 另外 / 此外 / 顺便 / 还有 / 并且 / 再者 / 然后 / 接着」开头，
   且该分句含疑问词，或接着提出要求（「以及介绍一下…」）。
3. **两个及以上分句各自在提问**（含疑问标志词，或「哪 + 量词」）。

第 3 条有两个排除，都是为了不误伤合法单问：

- **是非式铺场景不算第二问**：「有没有遇到过 X 的情况，你当时是怎么处理的」——
  第一分句在铺前提，不是真的要候选人回答是或否。
- **正反两面对照算一个请求**：「适合解决什么问题，不适合解决什么问题」——
  第二分句是第一分句加否定前缀的复述。

疑问词表包含：怎么/如何/为什么/为何/是什么/什么/哪些/哪个/哪一/哪几/哪种/是否/有没有/
会不会/能不能/能否/多少/几条/几个/几种/多大/吗/呢，外加 `_WHICH_MEASURE_PATTERN`
兜「哪 + 量词」（哪条 / 哪次 / 哪层）。最后这个模式是线上实测补的——
「对应哪条业务数据」第一版规则漏了，标注集里没有这种表达，只有真跑才会遇到。

## 5. 怎么验证规则真的生效

**不能只信计数器。** 计数器口径为 0 不等于人工口径为 0。

### 5.1 标注集回归

把历史盲评过的题面 + D4 分数整理成标注集，`D4 == 3` 视为两问正例，
直接量精确率 / 召回率。当前基线（192 条标注，14 条正例）：**命中 14/14，误报 0**。

新增规则时先在这个标注集上跑，别只看单元测试——单元测试是你挑的例子，
标注集是真实产出。

### 5.2 抽样跑批

用 `backend/scripts/quality_sampling/run_sampling.py`（见该目录 README）。
关键参数：

```bash
# 只看追问（第 2 轮之后），每组 4 轮 × 12 场景 = 48 道
python scripts/quality_sampling/run_sampling.py \
  --group all --single-samples 0 --rounds 5
```

`--single-samples 0` 跳过单题采样，只跑完整面试；追问样本才有内容，
开场题（自我介绍）没有思考成本，用它比较延迟会得出错误结论。

### 5.3 盲评口径

出题质量用 D4（单题合规）打分：5 = 单一请求可回答；4 = 单一请求但追加限定；
3 = 两个并列疑问；2 = 截断丢内容 / 泄漏评价；1 = 不成立。

**先评分后解盲**，剥掉 group / session / round 字段再给人评分。单人评分的主观偏差
在 D4 这种维度上是真实存在的，关键结论建议两人交叉。

## 6. 历史数据（供以后对比）

### 单题合规 D4

| 测量 | 范围 | 关思考 | 开思考 | 差值 |
|---|---|---|---|---|
| AIC-80 | 12 场景全维 | 4.668 | 4.781 | +0.113 |
| AIC-83 | 72 道开场题 | 4.944 | 4.889 | −0.056 |
| AIC-85 | 96 道追问 | 4.521 | 4.771 | +0.250 |

**符号翻了三次，幅度都在 ±0.25 以内，置信区间全部跨零。** 结论是「测不出差别」，
不是「开思考略好」。

### 延迟（追问，首 token）

| 组 | P50 | P90 |
|---|---|---|
| disabled | 627ms | 811ms |
| enabled | 2792ms | 4765ms |

约 4.5 倍。开场题两组都在 1.3 秒左右——那种题没有思考成本，**不要用开场题比较延迟**。

## 7. 已知限制

- **检测是规则不是模型**，形态之外的表达会漏（例如两种完全不重叠的问法）。
  192 条上 0 漏检不代表无限样本上 0 漏检。
- **量表饱和**：D1 针对性、D2 决策合理性、D3 难度匹配长期在 4.8~5.0，
  用这几个维度判断两组差异没有分辨力。要测「追问深度」得重新设计不饱和的锚点，
  并且改成 A/B 强制二选一，而不是打绝对分。
- **有效样本量按场次算，不按题算**。同一场的几道追问共享上下文和模拟器，
  逐题当独立样本会把置信区间压窄。
- **抽样脚本是外挂的**，不在 `app/` 依赖里，出题链路接口一变就会失效
  （AIC-82 的 async 改造就打断过一次）。改完出题链路记得回归它。
